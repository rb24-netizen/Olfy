The consumer app, research Lab, sensor controls and database are in one project. You can prepare and practice now, before the sensor arrives.

Open Olfy on your Mac.

1
Unzip Olfy_Starter.zip.

Move the extracted olfy_1_1 folder to Downloads. Open this guide from inside that folder.

2
Double-click Start_Olfy.command.

A Terminal window installs the Python dependencies on first launch and opens the setup screen. Keep Terminal open while you use Olfy.

3
Click “Run full practice test.”

Check the workspace, rehearse the pipeline, then save your first experiment plan. No sensor or API key is needed.

If macOS will not open the launcher

Open Terminal and paste this if the folder is in Downloads:

bash ~/Downloads/olfy_1_1/start.sh --setup

If the folder is somewhere else, type cd in Terminal, drag the extracted folder into the window, press Return, then run bash start.sh --setup.

Olfy accepts Python 3.11–3.13. If the launcher says Python is missing, use the official Python macOS installer for a supported version, reopen Terminal, and retry. Node, accounts and API keys are not needed. Initial dependency downloads need internet.

If you already have an earlier Olfy folder

Finish recording in the old app and use its full data backup. Keep your existing data folder. Extract this update separately; move a copy of that data folder into this project before launching, or restore a backup into a fresh data folder. Do not replace your recordings with an empty catalogue export.

Restore from the new project folder:

bash start.sh --restore-backup /full/path/Olfy_Data_Backup.zip --data-dir /full/path/new-empty-data

Launch the restored workspace with the same --data-dir option. Restoring refuses to overwrite existing data.

Setup & practice ↗Consumer app ↗Research Lab ↗

If another program uses port 8765, run bash start.sh --port 8766 --setup, then set the port above to 8766. Launching twice with the same data folder and port reopens the running app.

Do this now.

  1. Run the six-step practice test. It uses a temporary generated dataset.
  2. Try the scan circle in the consumer app’s Demo mode. Save a result and reopen it in Saved.
  3. Start with two perfumes you already own or can borrow. Choose their exact variants in the setup screen. Save a plan and download its CSV checklist.
  4. Use “Explore generated examples in Lab” to inspect curves and training on a held-out day.
  5. Optional: install the sensor drivers before delivery.

Do this on delivery.

  1. Connect your supported sensor with a USB data cable.
  2. Open Lab in Real sensor mode. Connect and inspect live readings.
  3. Condition and warm up in clean air using the manufacturer guidance supplied with your hardware.
  4. Choose a planned sample in Lab. Enter the actual bottle ID and verify the sample conditions.
  5. Record clean air → perfume exposure → recovery. The app stores the raw curve and fingerprint with the exact perfume ID.

Driver setup.

For the Adafruit BME688 breakout + MCP2221 bridge + QT cable, stop the running app with Control+C and run this from the project folder:

bash start.sh --hardware --setup

For a USB serial board streaming the documented Olfy JSON protocol:

bash start.sh --serial --setup

Add --prepare to install dependencies without starting the app. The BME688 bridge adapter uses its Python driver; a custom serial board needs matching firmware. Wireless accessory firmware is a later hardware task.

Keep your recordings.

Your data folder holds recordings, catalogue measurements, the saved collection, the experiment plan and model history. Back up from the setup screen or Lab → Dataset → Full data backup. Backups require no active scan. Press Control+C in Terminal to stop Olfy.

Double-click Check_Olfy.command for local diagnostic checks. You can also download diagnostics from the setup screen. Reopening the app preserves your data.

What is ready, and what still needs the sensor?

The UI, acquisition controls, typed sensor contract, real/demo separation, 50 perfume identities, reference indexing, 12-feature pipeline, model evaluation, rejection guards, sample planning and backup/restore are implemented.

The 50 catalogue identities are optional collection targets. You can begin with two perfumes and grow the measured library gradually. The shipped catalogue has no measured perfume references. The software does not reconstruct ingredients or cancel ethanol. The 10-second consumer capture saves raw readings; the current identification workflow uses longer three-phase references. Physical BME688 behavior, M1/macOS/Safari operation, real perfume accuracy and a wireless phone accessory still need direct validation.

This guide works offline. The connected app runs locally after setup. Generated examples demonstrate software behavior; they are not measured perfume fingerprints.
